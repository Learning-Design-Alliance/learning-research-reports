# Reproducing Paper II

Paper II ("What learner records can say about a prerequisite edge") is the article of this release. Its
analysis code is published with it in `code/`, and one script, `reproduce.py`, reruns every analysis the
release file declares and compares each output with the published one. Most analyses read a licensed
corpus of learner records, which the licences do not let us redistribute: you obtain each corpus from its
provider and point an environment variable at it. The rest (every synthetic detection floor, the
simulations, and the steps that read only committed outputs) need nothing but Python.

## 1. Run what needs no corpus (minutes)

```bash
pip install numpy scipy            # pandas, openpyxl and statsmodels for the trajectory-order step
python3 reproduce.py --no-corpus --quick
```

This reruns the floors and summaries that read no learner record and checks them byte for byte, for
example the Q-matrix floor and summary, the lag-band and domain floors, the planted conjunctive gate, the
registered-rule rescoring of the kappa levers, the filter re-check's comparison, the cross-curricular fit
without XES3G5M, and the edge-release power arithmetic. Drop `--quick` to add the slow synthetic steps
(orientation sweep, stability selection, the item-level floors, the ECPE check), which take from minutes
to hours each.

## 2. Reproduce everything your corpora allow

```bash
export XES_DIR=... ASSIST_DIR=... EEDI_ZIP=... EEDI_ANSWERS=...   # whichever you hold
python3 reproduce.py               # or --only rq3, --only rq1-qmatrix, --list to see every step
```

It copies `code/` to a working folder (`--work`, default `./reproduction`), runs each analysis exactly as
`1.0.0.yaml` (`analyses:`) records it, from the study's own directory, and compares each output byte for
byte with the published copy. It never changes `code/`. Steps run in order, so a floor regenerated by one
step is the floor the next reads. Each step ends **MATCH**, **DIFFERS** (with the file), **SKIPPED** (with
what is missing), **TIMEOUT** (with `--timeout`) or **FAILED**. A registered floor that fails exits 1 by
design (the surmise, lag-forgetting, calibration and kappa-bar floors); its record is still compared.

## 3. Re-run the headline numbers in the notebooks (seconds)

`notebooks/` holds one Jupyter notebook for each research question: `rq1-existence-direction.ipynb`,
`rq2-reliability.ipynb`, `rq3-validity.ipynb`, `rq4-usefulness.ipynb` and `rq5-what-is-identified.ipynb`.
Each recomputes its question's headline numbers from the aggregate outputs in `code/` and asserts each
against the value the paper prints, so a notebook that runs to the end has reproduced them. None needs a
corpus. Open them from this folder or from `notebooks/` (they find `code/` in the folders above them), or
set `RELEASE_DIR` to this folder. They need NumPy and Jupyter (`pip install numpy jupyter`). The RQ1
notebook has one optional cell that counts ASSISTments 2012-13's learners and skills from the corpus; it
is skipped, with a message, when the corpus is not there. The same notebooks, already executed, are in
the HTML report after the answer to each question.

## 4. Read the code

`code/` keeps the layout of the authors' repository, so every path the article gives resolves inside it.
Each study is a folder under `code/studies/`: its script's opening docstring is the primary record of the
design, the controls, the detection floor and, where there is one, the pre-registered verdict strings;
its `README.md` says what was asked and what came back; `out/` holds the published aggregate outputs.
`1.0.0.yaml` records, for each analysis, its exact invocation, the commit that last changed it, its
corpora and whether it was pre-specified. `code-manifest.txt` lists what `code/` holds and
`code/SHA256SUMS` hashes every file.

## What cannot be reproduced from this release

- **The model calls.** Building the graph of Section 4.6 (`e2e.py build`), its coverage judge (inside
  `e2e.py analyse`, so the whole of that step), the tagger on the expert's KCs (`expert_tags.py tag`), the
  cluster maps (`invariance.py map`) and the translations in the human coding sample (`human_codes.py
  sample`) called hosted models. The code is published and every recorded output is in `code/`
  (`build/`, `out/unit-map.json`, the spend logs); the prompts cannot be re-sent. `reproduce.py` lists
  these steps and always skips them. `1.0.0.yaml` declares the calls of each as an analysis of its own,
  its id ending in `-model-calls`, whose inputs are the authored item content it sent (question text,
  skill and unit names, standards descriptions); no learner record was sent. The AUCs of Table 10 are recomputed by the follow-up and control
  steps that import `e2e.py`'s model without calling one (`rq4-kc-tree` first reproduces M1 and M2
  exactly).
- **The deep models.** `rq4-dkt-routes-simplekt` and `rq4-dkt-routes-akt` (`dkt_routes.py --pod`) train
  simpleKT and AKT on CUDA graphics processors, download XES3G5M from its distributor's link and a
  public text encoder, and write to `$DKT_WORK/out` (default `/w/out`). Both floors failed, so neither
  reached the real responses; the floors took about three hours on four L40S processors.
  `reproduce.py` lists the two steps and always skips them. Their outputs are published in
  `studies/end-to-end/xes3g5m-dkt-routes/out/`, and `python3 dkt_routes.py --smoke` checks the code end
  to end on fake data, on a CPU, in a few minutes.
- **The human coding.** `human_codes.py score` reads the coder's returned workbook, which is not
  published; `out/human-codes.json` holds the person's codes and `out/human-agreement.json` the scoring.
- **Corpora we do not redistribute**, listed above. Two inputs were not hashed when they were read: the
  ds1190 per-sample exports (`S2_AM_Blocked`, `S2_MA_Blocked`) read by `rq3-ds1190-order`, and the
  Junyi rating files and MOOCCubeX `entities/user.json`, which were hashed later from the same route
  (the release file says so).
- **Every analysis declared in `1.0.0.yaml` has a step here.** The analyses that only the earlier
  drafts used were removed from the release when it was corrected to describe this article only.

## Notes

- The atlas step (`rq1-atlas`) compares the rows of `out/atlas.json` as a set: a full run writes them in
  discovery order, while the published file lists them in the order single-corpus reruns (`--only`)
  merged them.
- The kappa-bar floor (`rq2-kappa-bar-floor`) was published from an earlier commit of `kappa_bar.py`;
  the script as declared adds a `latent_gate` field to each point, so the step compares every other value
  and ignores that field.
- Four steps write their own wall-clock time into the output they are compared on
  (`rq5-iita-dense-floor`, `rq5-pairscan-floor`, `rq5-ecpe-floor`, `rq5-ecpe`), which no rerun reproduces.
  They compare every field except `seconds`, `seconds_per_set`, `seconds_per_fit` and
  `calibrate_seconds`.
- The expert-tree floor (`rq4-kc-tree-floor`) moves in the last digits of some estimates between
  machines (1e-16 to 4e-9 on a 2026-10-09 rerun), from floating-point summation order. It compares text
  and integers exactly and floats to a relative 1e-6.
- The Junyi taxonomy control (`rq3-junyi-taxonomy`) needs `DS1275_DIR` as well as `JUNYI_DIR`, and is
  skipped without it.
- `iita_dense.py` and `iita_pairscan.py` write their worker count into the output, so the steps pass the
  `--workers` the published run used. The remnant steps run with `OMP_NUM_THREADS=1`, as recorded.
- `lag_forgetting_v2.py floor` resumes from per-world parts under `out/floor_parts/`; the step deletes
  them in the working copy first, so the floor is recomputed rather than reassembled. The Eedi floor
  takes hours.
- `e2e.py analyse` refuses to run when `build/` shows uncommitted changes under git; run it outside a
  git working tree (the default `--work` folder inside this release directory is inside one when the
  release sits in its repository).
- Three packaged files name a scratch directory of the machine the analyses ran on:
  `shared/paths.py` (a fallback used only if that directory exists),
  `studies/identifiability/coarse-grain/register_order.py` (the default `--src` of the course-order
  step, which `reproduce.py` overrides) and `studies/identifiability/identifiability/qmatrix.py` (read
  only by that module's own loaders; the Q-matrix steps call just its `check`).
- While the release is under embargo, its Markdown, YAML and `.txt` files carry one embargo line, removed
  at publication. `SHA256SUMS` hashes the files without it, and `reproduce.py` compares outputs without
  it.
