# Per-case model outputs: data dictionary

Data file `per-case-model-outputs.jsonl`, shipped beside the release file `1.0.0.yaml` of research
release `ai-grader-reliability-2026` and declared there as dataset `per-case-model-outputs` (sha256,
line count and size are in that record). It holds, for every model run behind a re-test figure in
the release, each graded case's ids, the label or exemplar marks shown in each arm, the human score
and the model's mark in each arm. **It holds no answer, program or essay text, no grader rationale
or feedback text, and no demographic field.**

Generated by `studies/measurement/grader-eval/analyses/strip_dumps.py` (a path inside the release's
`code/` package) from the 32 per-case harness dumps whose SHA-256 values are in
`studies/measurement/grader-eval/analyses/per-case-dumps.sha256`. The full
dumps are kept privately, with those hashes. Each `run` line below names its source dump and that
dump's SHA-256. The script is deterministic: the same dumps always give the same bytes.

## Format

JSON Lines, UTF-8, one object per line. Every object has a `record` key.

- **32 `record: "run"` lines come first**, one per model run (or sampling draw), in the order of
  `per-case-dumps.sha256`.
- **14,260 `record: "case"` lines follow**, one per graded case per run, grouped by run in that
  order. Within a run, cases keep the harness's order.

`pandas.read_json(path, lines=True)` reads the file. Filter on `record` to separate the two kinds.

### `run` lines

| key | meaning |
| --- | --- |
| `run` | run id: the source dump's path without `.json`, e.g. `grader-vi/swap-gemini` |
| `corpus` | `jorgpt`, `mohler`, `menagerie` or `asap2` |
| `model` | model id as the harness called it (`provider:model`); an object `{lite, standard}` for the pooling run; `null` for a sampling draw, which grades nothing |
| `source`, `source_sha256` | the original dump's file name and SHA-256 |
| `cases` | number of `case` lines for this run |
| `row_keys`, `header_keys` | the original key order of a case and of the dump's header, so the dump can be rebuilt exactly |
| `removed_row_keys`, `removed_header_keys` | keys left out of this file: `groups` and `cell` (ASAP 2.0 demographics and the sampling cell derived from them), and `resumedFrom` (a local file path) |
| `header` | the run's header as the harness wrote it, less the removed key: run stamp, temperature and reasoning settings, arms, scale, labels, sampling salt and quotas, call, failure and token counts, and the request-configuration record (prompt bodies reduced to hashes by the harness) |

### `case` lines

`record`, `run`, `corpus` and `model` as above, then the harness's own keys, in its order:

| key | meaning |
| --- | --- |
| `id` | the case id **as the corpus publishes it**: JorGPT `entry_id`; Mohler `id` (`E<module>.Q<question>.A<answer>`); Menagerie `<assignment_number>\|<skill>`; ASAP 2.0 `essay_id` |
| `learnerId` | JorGPT `student_anom_id`, the corpus's anonymised student id |
| `questionId` | JorGPT `question_id`; Mohler `E<module>.Q<question>`; Menagerie the rubric dimension (`skill`) |
| `cluster` | the bootstrap cluster: JorGPT `student_anom_id`, Mohler question, Menagerie `assignment_number` |
| `dim` | Menagerie rubric dimension; `null` elsewhere |
| `prompt` | ASAP 2.0 `prompt_name` (the task title, not the student's text) |
| `tail` | `high` or `low`: which tail of held-out attainment the case was drawn from (JorGPT) |
| `human` | the human reference score, on the corpus's own scale: JorGPT `teacher_grade` (0-10); Mohler `score_avg`, the mean of two raters (0-5); Menagerie the mean of the graders' letter grades mapped to 0-13; ASAP 2.0 `score` (1-6) |
| `max` | the top of the scale the model marked on (label-stability runs; JorGPT is re-marked out of 5 in the `jorgpt5` runs while `human` stays out of 10) |
| `chars`, `contextChars` | length in characters of the graded answer, and of the context each exemplar arm adds (numbers only) |
| `labelTrue`, `labelSwapped` | the attainment label shown in the true-label and swapped-label arms (0-10) |
| `labelHigh`, `labelLow` | the labels shown in the high and low arms, on the run's scale |
| `control`, `trueLabel`, `swappedLabel` | the model's mark with no label, the learner's own label, and the other tail's label |
| `high`, `low` | the model's mark under the high and the low label |
| `none`, `low`, `mid`, `high` (ASAP 2.0) | the model's mark with no label and under the assigned low (1.9/6), mid (3/6, Qwen only) and high (4.2/6) labels |
| `no history (control)`, `prior attempt, low grade`, `prior attempt, high grade`, `prior attempt, low, NO mark`, `prior attempt, high, NO mark` | the model's mark in each attempt-history arm |
| `lite`, `standard` | pooling run: nine repeated marks from the lite model, one from the standard model |
| `anchorIds`, `trueMarks`, `rotation` | exemplar runs: the corpus ids of the three exemplar answers, their teacher marks, and the presentation rotation |
| `shown` | exemplar runs: the marks shown on the three exemplars in each arm (`null` where no marks are shown) |
| `scores` | exemplar runs: the model's mark in each arm (`control`, `ungraded`, `correct`, `shuffled`, `shiftUp`, `shiftDown`) |

A mark of `null` is a call that failed after retries; the analyses drop or count those as their
docstrings say.

## The demographic fields are not here

The two ASAP 2.0 runs (`grader-vi-groups/run-qwen`, `grader-vi-groups/run-gpt41mini`) were analysed
by English-learner, economic, disability, gender and race/ethnicity status. Those fields, and the
sampling cell derived from them, are left out. They are public in the corpus and re-join by
`essay_id`:

```
python3 studies/measurement/grader-eval/analyses/strip_dumps.py rebuild --data <this folder> \
    --out <dir> --asap2 <ASAP2_train_sourcetexts.csv>
```

writes the 32 dumps in the layout the analyses read, with the fields re-joined. `strip_dumps.py verify` checks that the rebuilt dumps equal the originals in every row and header field except `resumedFrom`. The rebuilt files are written as the harness wrote them (JSON, indent 2, no trailing newline), so 30 of the 32 are byte-identical to the originals and match `per-case-dumps.sha256`; the two ASAP 2.0 files differ only by `resumedFrom`. Their rebuilt hashes are deterministic and listed in `studies/measurement/grader-eval/analyses/per-case-dumps.rebuilt.sha256`, which `grader-label-dose` and `strip_dumps.py verify` accept beside the originals. Analyses that check each dump's hash (grader-ceiling-robustness, and grader-label-dose with the rebuilt-hash list) therefore run on the rebuilt files: their outputs regenerate byte for byte.
